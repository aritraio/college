# One-Liner Questions

1. **Question:** What are User Requirements?
**Answer:** High-level abstract statements of what the system should provide and the constraints under which it must operate, written for customers.

2. **Question:** What are System Requirements?
**Answer:** Detailed descriptions of the software system's functions, services, and operational constraints.

3. **Question:** Define Requirement Elicitation.
**Answer:** The process of gathering system requirements from stakeholders, users, and existing documentation.

4. **Question:** What does Interviewing involve in requirement elicitation?
**Answer:** A direct elicitation technique involving structured or unstructured conversations with stakeholders to gather requirements.

5. **Question:** What are Scenarios in requirements engineering?
**Answer:** Real-life examples of how a system can be used, helping to understand practical interactions and extract requirements.

6. **Question:** What is a Logical DFD?
**Answer:** A process model that shows *what* the system does and how data flows, independent of its physical implementation.

7. **Question:** What is a Physical DFD?
**Answer:** A process model that shows *how* the logical system is physically implemented, detailing hardware, software, and specific personnel.

8. **Question:** What is a Feasibility Study?
**Answer:** A short, focused study conducted to determine if a proposed system is worth building based on current technology, budget, and business objectives.

9. **Question:** What is Requirement Validation?
**Answer:** The process of checking that the documented requirements truly define the system that the customer wants.

10. **Question:** Define Use-case.
**Answer:** A formal description of a system's behavior as it responds to a request from an external user or system (actor).
