# Short Answer Questions

**1. Briefly explain the difference between black-box and white-box testing. (3 marks)**
**Answer:** Black-box testing evaluates the functionality of the software based purely on input-output interactions without any knowledge of the internal code structure. It is used to ensure the software meets its requirements. White-box testing, conversely, examines the internal logic, algorithms, and structural execution paths of the code. The tester must have access to and understand the source code to design test cases that cover all independent paths, loops, and conditions.

**2. Why is software size estimation a necessary first step in project planning, and how do LOC and Function Points differ? (4 marks)**
**Answer:** Software size estimation is necessary because it forms the baseline for predicting the effort, cost, and duration of a project. Without a size estimate, models like COCOMO II cannot compute accurate budgets or schedules. Lines of Code (LOC) measures size directly by counting text lines, making it highly dependent on the programming language and developer style. Function Points (FP) measure size indirectly based on the functionality delivered to the user (e.g., inputs, outputs, inquiries), making it language-independent and measurable earlier in the requirement phase.

**3. Define the Capability Maturity Model (CMM) and state its primary purpose in quality frameworks. (3 marks)**
**Answer:** The Capability Maturity Model (CMM) is a methodology used to assess and refine an organization's software development process. Its primary purpose is to provide a structured framework for continuous process improvement, guiding organizations from chaotic, unpredictable development practices through a series of maturity levels toward highly optimized and controlled processes.

**4. What is the RMMM framework in risk management? (3 marks)**
**Answer:** RMMM stands for Risk Mitigation, Monitoring, and Management. It is a comprehensive plan that outlines how an organization will handle project risks. **Mitigation** involves proactive steps to reduce the likelihood or impact of a risk. **Monitoring** involves tracking project indicators to determine if a risk is becoming more or less likely. **Management** (or contingency planning) defines the reactive steps to be taken if the risk actually materializes.

**5. How does Earned Value Analysis assist a project manager in scheduling? (3 marks)**
**Answer:** Earned Value Analysis provides a quantitative measure of project progress by combining schedule and cost metrics. Instead of just looking at the calendar or the budget consumed, it calculates the "value" of the work actually completed. This allows a project manager to definitively state whether a project is ahead of or behind schedule, and under or over budget, enabling early detection of schedule slippage.
